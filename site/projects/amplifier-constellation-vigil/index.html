Where it fits

An always-on engine that an Agent Instance can select. Outside it is an ordinary ACP agent; inside, a daemon keeps memory and a schedule and drives a runtime of your choice.

Supporting component. Supports: Agent Instance.

  • Constellation Instance uses Vigil.
  • Vigil contains ACP bridge and conductor.
  • Vigil contains Follow-ups and background work.
  • Vigil contains Mind: memory and presence brief.
  • ACP bridge and conductor uses Selected runtime (any ACP agent).
  • Mind: memory and presence brief uses Decision models (optional).

Requirements, map sources, and implementation details
  • Vigil is an independent open-source project maintained in its own repository. It is not one of the Microsoft components in the Constellation family index.
  • Vigil is an engine an Agent Instance selects, not an Agent Instance itself: identity, tokens, attention and context sources stay with the Instance.
  • The default runtime is Constellation Runtime; any other ACP agent can be the main runtime or take delegated work.
  • Experiences are unchanged and attach to the Instance as before. Each experience still decides when the agent may speak.
  • Decision models are optional; without one Vigil falls back to plain rules.
  • Tested on Linux with systemd user services. The map shows scope, not a compatibility claim for every ACP agent or host.

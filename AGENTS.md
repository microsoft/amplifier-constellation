# Working in the Constellation umbrella

Use [Amplifier Converge](https://github.com/microsoft/amplifier-converge) as the
collaboration method. Read `docs/VISION.md` and the contracts for the next outcome.
Derive the gap by inspecting current source, capabilities and relevant behavior;
do not maintain a parallel umbrella status or gap inventory. `docs/working-together.md`
explains the local practice. Do not load every contract or historical conversation
by default.

- Use `family.toml` to find the Microsoft component that owns a behavior. This
  repository owns shared direction and composition, not every implementation.
- Inspect current source and relevant evidence. Distinguish intended behavior,
  accepted commitments, implementation and verified outcomes. A draft does not
  silently replace an agreement.
- Make ordinary decisions within delegated authority. Prepare a concrete choice
  when a shared promise or reserved decision must change; continue unaffected
  work. Do not add routine approval gates.
- Give shared promises one home. Keep detailed schemas, protocol behavior and
  tests with their serving component; link them here. Guides and diagrams explain
  those promises and do not create a second API specification.
- Name an outcome owner, affected connections and a meaningful combined check in
  the existing work record. Carry changed direction into active work; a document
  edit alone is not completion.
- Keep current direction concise. Do not append running release histories or
  summaries of gaps that future contributors must maintain. Link evidence only
  when it supports a current claim or decision.
- Keep credentials, personal profiles, transcripts, deployment details and private
  experiments outside this publication checkout.
- For documentation changes, inspect the full changed passages, check links and
  visuals, and walk through a newcomer and a changed-boundary scenario. A prose
  walkthrough is not proof of deployed behavior.

Existing repository permissions and assignment authority still govern publication
and operations. This file grants neither access to installations nor authority to
change another owner's commitments.
